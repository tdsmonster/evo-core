## 0. EVO-CORE X 架构对齐前提

在 EVO-CORE X 体系下，Agent 的自进化与执行不再依赖单一模型或模糊的主观自省，而是由**四大自主认知引擎**协同驱动：

```
[世界模型 (World Model: M6)] ➔ 实时探测环境拓扑与服务健康
[知识引擎 (Knowledge: M2, M3, M9)] ➔ 经验 5 级压缩，编译期消灭冲突
[证据引擎 (Evidence: M1, M4, M7, M8)] ➔ 短生命周期沙箱 + 零 LLM 机器单测硬断言
[对齐引擎 (Alignment: M0, M5, M10)] ➔ 三层异构算力调度 + 成本与安全边界管控
```

## 1. 三类异构算力分型 (Heterogeneous Compute Profiles)

| 算力分型 | 硬件画像与拓扑 | EVO-CORE X 算力分工策略 |
|---|---|---|
| **类型 1: 极简轻量型 (Low-Spec)** | 内存 ≤8GB / 树莓派 / 免费云容器 | 纯云端 API 做决策裁判 (Tier 1) + 本地纯规则与沙箱单测执行 (Tier 3) |
| **类型 2: 端侧混合型 (Mid-Spec / 黄金主流)** | 内存 16~32GB 统一内存 / 入门 GPU | **云端高阶裁判 (Tier 1) + 本地小模型 7B~35B 离线脱敏提炼 (Tier 2) + 高吞吐无状态工兵池 (Tier 3)** |
| **类型 3: 本地极客型 (High-Spec)** | 内存 ≥64GB / 高显存工作站 | 本地中大模型全托管闭环，全离线沙箱与机器单测验证 |

## 3. 核心设计与防踩坑原则 (EVO-CORE X 铁律)

1. **机器单测优先 (Evidence Gate)**: 严禁将未经 `unittest` 机器断言的代码直接合入生产系统。
2. **用完即毁 0 内存泄漏 (Ephemeral Sandboxing)**: 代码生成与探索必须在隔离临时目录进行，测试完成后立即清理，保障系统常驻内存绿色健康。
3. **编译期消灭冲突 (Compile-Time Knowledge Safety)**: 技能合并与去重在离线压缩期完成，严禁在运行时向 Prompt 注入互相矛盾的冗余规则。
