# M6 环境自愈模块

> **来源论文**: Continual Harness (arXiv:2605.09998) + SkVM (arXiv:2604.03088v3)
> **依赖**: 无
> **适用**: 所有档位（常驻服务/守护进程的场景必选）

---

## 论文核心主张

- **Continual Harness**: 长程运行中不停机热更新；监控死循环/停滞信号并在线修复；自愈。
- **SkVM**: AOT 环境绑定——安装期预检依赖，避免运行期"缺依赖崩溃"。

## AI 可解析核心

### ① AOT 依赖预检（调用前幂等自检）

对复杂能力（GUI 自动化/浏览器 CDP/文档解析等），执行前检查四类依赖：

| 检查项 | 判定 |
|---|---|
| CLI 命令 | `shutil.which(cmd)` 存在 |
| Python 包 | `importlib.util.find_spec(pkg)` 非空 |
| 端口 | TCP connect 成功 |
| 环境变量 | 存在且非空（如 PATH） |

缺依赖 → 输出修复指令，**禁止运行期静默崩溃**。

### ② 看门狗自愈规则

```
常驻进程 → 探针/KeepAlive 自愈
失败 → 动态退避: 30s → 60s → 120s → 300s
告警 → 冷却期（防轰炸）
```

### ③ 自愈边界（关键）

- 自愈机制**必须保留显式状态日志**，区分「服务假死」（自动拉起）与「有意停机」（人工 kill，不拉起）；
- 防止自愈掩盖人工调试意图。

### ④ 后台环境一致性

- 后台调度（cron/守护进程）与终端交互环境常存在 PATH 不一致；
- 规则: 脚本调用解释器/外部工具时**显式指定绝对路径或预加载完整环境**。

## 适用场景

- 24 小时常驻、依赖外部服务的 Agent——防静默失效、防告警轰炸、防进程泄漏。
